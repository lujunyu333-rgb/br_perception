   256 ### 2.2 `src/lidar/ground_segmenter.hpp / .cpp`
   257
   258 **输入**：预处理后的点云
   259 **输出**：地面点云 + 非地面点云 + 地平面方程
   260
   261 **任务清单**：

   263 - [ ] 距离阈值从 `lidar_params.yaml` 读取，针对 L1/L2 不同高度使用不同阈值

  1145 ## 十三、关键设计原则
  1146
  1147 ### 13.1 传感器互补矩阵（团队共识）
  1148
  1149 这是 BR 感知系统最核心的设计理念，整个团队需要理解清楚：
  1150
  1151 ```
  1152                     雷达能做的          相机能做的
  1153 地球方块位置         ★★★ 精确3D         ★★☆ 2D+颜色
  1154 天空方块位置         ★★★ 精确3D         ★★★ 2D+面颜色
  1155 天空方块朝上面颜色     ☆☆☆ 做不到         ★★★ 非常准
  1156 穆斯蒂卡检测          ★★☆ 柱上物体       ★★★ 金色球确认
  1157 建筑位塔高度          ★★★ 直接测高       ★★☆ 可以看
  1158 建筑位归属            ☆☆☆ 做不到         ★★★ 看颜色
  1159 敌方机器人            ★★★ 360°+测速     ★★☆ 前向只有
  1160 围栏/边界             ★★★ 线特征         ★★☆ 颜色分段
  1161 ```
  1162
  1163 ### 13.2 性能预算
  1164
  1165 ```
  1166 总延迟预算：80ms (采集→串口发送)
  1167
  1168 雷达通路：
  1169   采集(10ms) + 预处理(5ms) + 地面分割(8ms) +
  1170   圆柱检测(3ms) + 聚类(5ms) + 建筑位分析(3ms) = 34ms
  1171
  1172 相机通路：
  1173   采集(16ms) + 预处理(2ms) + ONNX Runtime推理(25ms) +
  1174   HSV后处理(3ms) = 36ms
  1175
  1176 融合 + 编码 + 发送：10ms
  1177
  1178 总端到端：max(34, 46) + 10 = 56ms < 80ms ✓

**v1.2 修订（评审建议）**：ONNX CPU fp32 实际延迟可能 30-35ms，聚类在点云密集时可能膨胀，预算改为预留 50% 余量 → 目标 ≤53ms：
```
修订后相机通路: 采集(16ms) + 预处理(2ms) + ONNX推理(30ms, 按实测上限) + HSV后处理(3ms) = 51ms
动态 QoS: 目标数>10 或推理>30ms → 输入分辨率降至 480×288, 推理预算恢复 ~20ms;
          后相机降频 30Hz→10Hz, 前后相机分时推理
匈牙利匹配: 目标数≤20(场地上限), O(n³)≈8000 次运算 < 0.1ms, 10ms 预算充足
总端到端: max(34, 51) + 10 = 61ms < 80ms ✓(动态 QoS 启用时回到 ~46ms)
```
  1179 ```

### 15.2 技术栈变更对照

| 项目 | 原方案 (v1.0) | 实际方案 (v1.1) | 变更原因 |
|------|--------------|----------------|---------|
| 计算平台 | Jetson Orin NX/Nano | GMKtec R5 6600H | 实际硬件 |
| CPU | ARM Cortex-A78AE 6-8核 | AMD Zen 3+ 6C12T @ 4.5GHz | — |
| GPU | NVIDIA Ampere 1024 CUDA | AMD RDNA2 6 CU (核显，不用于推理) | — |
| 推理框架 | TensorRT (CUDA) | ONNX Runtime CPU EP | AMD 无 CUDA |
| 模型格式 | .engine (TensorRT 编译产物) | .onnx (PyTorch 直接导出) | 通用格式 |
| YOLO 版本 | YOLOv8n/s | YOLOv8n (3.2M 参数) | 轻量够用 |
| 量化 | TensorRT INT8 | 不做量化 (fp32) | CPU 无 INT8 加速单元，量化反而更慢 |
| SIMD | NEON | AVX2 (Zen 3 自带) | ONNX Runtime 自动检测并使用 |
| 相机 | 工业RGB相机 × 2 | Intel RealSense 435i / 技彩工业相机 × 2 | 实际硬件 |
| 雷达 | Livox Mid-360 × 1 | Livox Mid-360 × 1 | 不变 |
| 温度监控 | tegrastats | /sys/class/hwmon | 通用 Linux 接口 |
| 性能预算 | 46ms 端到端 | 56ms 端到端 (< 80ms) | ONNX CPU 比 TensorRT 慢约 10ms |

### 15.3 AMD 平台性能预估

```
雷达通路 (全部 CPU，不变)：
  采集(10ms) + 预处理(5ms) + 地面分割(8ms) +
  圆柱检测(3ms) + 聚类(5ms) + 建筑位分析(3ms) = 34ms

相机通路 (ONNX Runtime CPU EP)：
  采集(16ms) + 预处理(2ms) + ONNX Runtime fp32推理(25ms) + HSV后处理(3ms) = 46ms

融合 + 编码 + 发送：10ms

总端到端：max(34, 46) + 10 = 56ms < 80ms OK 的预算内

说明：
  - YOLOv8n @ 640x384 输入，6C12T Zen 3 上 ONNX Runtime 实测 20-25ms
  - AVX2 自动向量化对 fp32 矩阵运算加速显著
  - 6 核物理核心：雷达1核 + 视觉1核 + 融合通信1核，剩余 3 核给系统和 ROS
  - RDNA2 核显不参与推理，仅用于显示输出和可视化
```

v1.7 修订与增补（在 v1.5 基础上优化）
一、版本说明
规则引用基线从中文 v1.0 译本改为官方英文 v1.1（robocon.org.cn 2026-08-28）。场地几何用确认坐标回填，缺项标注“图2待补”。本版新增定位与建图（SLAM）、导航、任务决策层三章，以承接“整条链路在这台主机规划”的目标；感知层增加“事件 + 资源台账”，为任务决策层提供数据。
二、规则基线修正（依据英文 v1.1，P0 级）
三、场地几何（确认坐标回填 + 图2待补）
等轴测图显示：天空棋盘在前右地面一带、穆斯蒂卡柱在后左地面、坡道在左侧、启动区在前下方——均非几何中心，坐标以图2为准。
四、新增：定位与建图（SLAM）要点
场地固定已知 → 不做探索式建图，做定位：FAST-LIO2 里程计 + 场地先验重定位（柱/建筑位 PnP 对齐）+ BR_RESET 位姿注入。
地图表示：每层独立 2D costmap（L1、L2）+ 层间转移边（楼梯口、L1 重试下放点）+ L1 边缘禁入带（防坠落）。依赖 OccupancyGrid；不做 3D ESDF/Voxblox（斜坡对轮式 BR 是机械限制，交给决策层）。退化处理与 ground_segmenter 坡上状态、odometry_reliable 联动（沿用 v1.5）。
五、新增：导航要点
全局：A*/Smac 在分层 costmap 上 + 层间图（不是一张 2D 平面连续规划）。局部：DWB / RPP（低速慢平台）；不引入 MPPI（避免与感知推理抢 CPU 核）。语义化：静态障碍来自场地几何（已建成塔=障碍，空地=可行），动态障碍来自融合语义目标。与 STM32 主控边界待定：若导航/决策放主机，协议需扩展（目标点/期望路径下发）。
六、新增：任务决策层（“任务优化”核心）
目标：180s 内最大化得分。转移 5/块；塔 L1 10/20/40、L2 20/40/80；穆斯蒂卡 250（需圣所达成 ≥2 完整塔且 ≥1 在共享区）。
结构：状态估计 → 价值评估（期望得分/风险）→ 行为调度（优先级）→ 执行。
关键输入（感知需补）：① 转运区交接台账（块进入/被取走、类型/颜色/时间 → TR 供给节奏）；② 对手威胁（对方 BR 在共享区塔边停留/翻顶）；③ 资源台账（剩余地球块、天空块朝向）；④ 圣所使命状态与风险（达成前共享区塔被翻会推迟使命）；⑤ 终场 5 秒纪律（宁可不放，也不要在蜂鸣时手持/碰块）。
风险：区域/推移违规 → 强制重试耗时间；终场手持 = 0 分。
七、感知增量（为决策层供数）
transfer_zone 台账字段（物品进入/取走/类型/颜色/时间）；Obstacle 增加“对己方塔威胁”标记 + “塔被触碰中”状态；剩余资源：存储区地球块计数（随 TR 取走变化）、天空块朝向跟踪；天空棋盘 12 块先验（已可按 240 格计算）→ 融合层跟踪；BR_RESET 增加“首次进入 L1”flag；穆斯蒂卡竞态监控（对手 TR 靠近柱时告警）。
